# RetailNetwork - симулякр распределённой системы.

## Описание
Проект `RetailNetwork` представляет собой систему, эмулирующую обработку кассовых событий. Система генерирует асинхронные события продажи/возврата и отправляет их в Kafka. Отуда они пересылаются в БД по которой можно получать отчёты через Rest API.

## Запуск

### Сборка и запуск:
Вспомогательные модули развёртываются как nuget-пакеты. Чтобы они попали в контейнеры нужно сперва опубликовать эти пакеты, а затем тиражировать их в папки сервисов. Для этого можно использовать скрипт `.\publish-paks.ps1`.

Когда пакеты тиражированы, развёртывание приложения осущетвляется командой
```bash
docker compose up --build -d
```

Все эти действия выполнияются также одним скриптом `.\build-up.ps1`.


## Архитектура

### Reports.Web
Модуль, предоставляющий Rest API для получения кассовых отчётов.
- На данный момент реализована единственная конечная точка, по которой возвращаются агрегированные данные по каждому товару для указанной кассы.
- Данные забираются из озенра данных (см. дальше)
- Данные кешируются в Redis и извлекаются/сохраняются посредством HybridCache
- Генерируется openapi-описание конечных точек, его можно посмотрть по пути http://localhost/scalar/v1

### Seq
Контейнер Seq управляет одноимённой колоночной БД, ориентированной на сбор журналов разных сервисов.
- Жруналы всех .net-сервисов собираются в структурированном виде посредством Serilog
- Seq имеет свой UI, доступный по пути http://localhost:5341/

### Озеро данных
Сервис накавливающий данные со всех касс для построения аналитических отчётов.
- Ванные хрнаться в OLAP-СУБД Clichouse
- Описание EF-моделей реализовано в проекте KassaEventDataBase
- В том же проекте описаны sql-миграции, автоматически формируемые из .net-миграций
- За выполнение миграций отвечает сервис ch-migrator 

### KassaReaderService
Сервис, читающий из Kafka очередь кассовых сообщений, и складывающий их в озеро данных.
- Очередь обрабатывается двумя работниками --- это и другое можно настроить в конфигурационном файле.

### Appache Kafka
Шина данных для сбора событий из распределённой сети касс.
- Реализован кластер из двух узлов (по честному надо не меньше трёх, но для целей проекта сойдёт и так).
- Одна очередь сконфигурирована на две партиции.
- Для взаимодействия из .Net-модулей используется пакет FluentKafka
- Настроена сериализация protobuf

### KassaEventSimulator
Сервис, отвечающий за отправку кассовых событий.

- Кассовые события генерируюся случаным образом
- Данные для генерации подтягиваются из БД Postgress
- EF-Модели для БД предоставляет модуль KassaEventDataBase
- В том же проекте описаны sql-миграции, автоматически формируемые из .net-миграций
- За выполнение миграций отвечает сервис pg-migrator 
- Использует `IAsyncEnumerable<KassaMessage>` для потоковой передачи событий.
- Поддерживает настройку задержки между отправкой событиями.


## Сопровождение

При изменениях в инфраструктурных проектах необходимо периодически публиковать и тиражировать их пакеты скриптом `.\publish-paks.ps1`.

Если меняются модели EF, тогда в *этом проекте* необходимо сначала сгенерировать .net-миграцию, а затем уже из них пересобрть sql-миграции:
```bash
dotnet ef migrations add <ИМЯ-МИГРАЦИИ>
.\generate-migrations.ps1
```
При пересборке контейнеров миграции применятся в БД
